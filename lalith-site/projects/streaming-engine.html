A high-throughput streaming engine

A market-data pipeline and matching engine in C++ and Python.

C++ · Python · River · Prometheus

Why I built it

I wanted to understand how trading systems stay fast when events arrive faster than a simple design can handle. To learn that, I built a small version end to end: an ingest pipeline, a matching engine, and a live model running on top of the stream.

How it works

market events
  → ingest (lock-free ring buffer)
  → limit order book (price-time matching)
  → trade events
      → Prometheus metrics
      → River model (live predictions)
  • Ingest. Events pass between threads through a lock-free ring buffer, so the producer and consumer never block each other on a lock.
  • Matching. An in-memory C++ limit order book matches orders by price-time priority and supports cancels and partial fills.
  • Outputs. Every trade is logged as an event to Prometheus, and a Python layer runs an online logistic regression model in River on the live stream to predict short-term events.

Performance

MetricResultConditions
Ingest throughput 100K events/sec Sustained
Ingest latency < 200 µs At 100K events/sec
End-to-end latency < 1 ms With 50K active orders in the book

What I learned

The biggest lesson was how much small optimizations add up. At 100K events a second, a few extra microseconds per event decide whether the pipeline keeps up or starts to fall behind. This changed how I think about performance, since speed in a system like this comes from many small decisions adding up.
